# AGENTS.md — rules for every AI agent in this repo (Claude Code, Codex, others)

`CLAUDE.md` only imports this file, so every agent reads the same rules. Humans: start with `README.md`.

**Now (November 2026):** demo at the AI Builders Congress (OpenCloud, Bangladesh), then onboarding real farmers. The July hackathon build is tag `tier0-stable`; the FutureMakers round added the phone channels (SMS, USSD, voice) and the two marketplaces.

**Read before your first task:** `README.md` (what it is, how to run it), `docs/MAP.md` (where everything lives), `docs/NOTES.md` (known traps, numbered; code cites them as "NOTES #13"), and the latest entries of `LOG.md`. When anything behaves strangely, re-read `docs/NOTES.md`; your bug is probably listed. `docs/product/PRD.md` is the product spec. Everything in `docs/archive/` and `docs/logs/` is history, not instructions.

## 0. Identity and boundaries

- **Single operator.** One agent works the whole tree, on branch `main` of the private repo `Shafin2954/urbora`. If the humans split work again, they will say so; then ask which half you own.
- `backend/schemas.py` is the shared contract. Changes must be additive (new optional fields, new literals) and each one gets a LOG.md entry with the reason.
- Never point two agents (Claude Code, Codex) at the same directory simultaneously.
- The product name is not final. Farmer-facing text takes it from `backend/branding.py` / `frontend/src/branding.js`; never hardcode it.

## 1. Logging protocol (mandatory)

- Current log: `LOG.md` (repo root). `docs/logs/LOG1.md`–`LOG3.md` are closed hackathon history. Append-only; never rewrite past entries. Date every entry's first line of the day (`# YYYY-MM-DD`).
- One entry per unit of work: feature done, decision taken, bug found/fixed, dependency added, approach abandoned.
- Written for humans: a tired teammate at 4am understands it in 20 seconds. Plain language.
- After an entry that adds, moves or changes the purpose of a file or folder, update `docs/MAP.md` so the next agent need not re-explore. If you don't know what something is, say so there.
- Save what you explored whenever possible, to avoid repeated exploration and token use.

Format:

```
## [HH:MM] <short title>
**Did:** what changed, which files.
**Decision:** what was decided (if any).
**Why:** one or two plain sentences.
**Rejected:** alternatives considered and why not. "none" if none.
**Impacts:** what a teammate or a later session needs to know, or "none".
```

- Decisions without code (e.g., "1 bigha = 33 decimal convention") get entries too. Silent decisions are the enemy.
- Abandoned an approach? Log it with the time it cost. That entry saves the next person from repeating it.

## 2. Hard technical rules

1. **The LLM never does arithmetic and never ranks crops.** Money/yield/dose/unit math → `backend/finance/` or `units.py`. Crop ranking → `crop_scorer.py` (deterministic, PRD §4). The model narrates tool outputs. A prompt letting the model compute or rank = bug; fix and log.
2. **No invented data.** Weather from Open-Meteo responses. Yields from crop.db. Doses from KB retrieval. Source unavailable → degrade honestly in the agent's reply ("তথ্য যথেষ্ট নয়") — never fabricate.
3. **Provenance is mandatory.** Every number reaching the UI carries a Provenance object (schemas.py). A number without provenance must not render. This is schema-enforced, not prompt-hoped.
4. **Weather labeling.** Every weather-derived claim carries `source_type: forecast | climatology`. Climatology is a planning assumption, never a prediction — wording rules in PRD §6 Tier0.2.
5. **Every tool call is traced, and traced redacted.** New tools must emit `tool_call`/`tool_result` SSE events with raw params/results. The emitter (`backend/api/sse.py`) redacts: password/appId/key/token/secret → `***`, phone/subscriberId → last 3 digits. Untraced tool = doesn't exist for judges. Unredacted trace = security bug.
6. **Generated artifacts carry their origin.** crop.db and any index are regenerated by committed scripts, with timestamps + git sha in a meta table. Prefer a maintained open-source tool over hand-rolling when it integrates cleanly (LOG.md tool-selection entry); record the choice and the rejected alternatives.
7. **Pin all dependencies** exactly on first add.
8. **Secrets never touch git.** `.env` / `.env.local` / `backend/.env` only; `.env.example` current; check diffs before push.
9. **Agent loop guards:** max 12 iterations/turn; token usage + cost per turn in the `done` event and console.
10. **Bangla-first:** farmer-facing text defaults to Bangla, mirrors user language. Internal reasoning, tool params, RAG queries (always English), trace, code comments: English. Western numerals in tables/computed values.
11. **Units:** internal = hectares/kg only; local units exist at intake/display edges via units.py. 1 bigha = 33 decimal = 0.1338 ha.
12. **Tests where they matter:** finance engine (incl. commission/fee/treatment cost), units.py, crop_scorer.py, trace redactor, channel menu state machines, SMS segment budgeting, marketplace ranking and order/offer state transitions. All tests live in `backend/tests/`; run `.venv/Scripts/python -m pytest backend/tests -q` before every push to `main`. No coverage theater on UI.
13. **Simulator honesty:** bdapps simulator matches documented shapes exactly, labeled `mode:"simulator"` in code, UI, README. Never present simulated as live. Checkout always has a confirmation step before charging.
14. **Scope order:** existing web flow stays green > channels (SMS, USSD, voice) > marketplaces > polish. Off-plan ideas go to LOG.md as proposals.
15. **Channels:** phone numbers are PII — stored as salted hashes for identity, redacted to the last 3 digits in every trace and log. A USSD screen never waits on the LLM (answers go async by SMS). SMS/USSD/voice text numbers come from tool outputs through templates, never from model prose. Simulated channels are labeled `simulator` exactly like payments (rule 13).
16. **Marketplace honesty:** every dealer, buyer, product and listing row carries `is_demo`; demo rows are labeled demo wherever they render. A price from a listing carries provenance naming the dealer and date.

## 3. Workflow rules

- Work on `main` (the only branch since the move to `Shafin2954/urbora`, 2026-11-10). Big or risky changes go on a short-lived branch and merge back into `main`.
- Small commits, imperative messages.
- Before every push to `main`: run the test suite (rule 12) + one manual end-to-end chat turn. Broken `main` is forbidden.
- `tier0-stable` must stay reachable: it is the known-good hackathon build. It lives in the old repo `Shafin2954/TeamFixeth_AgriSense` (local remote `agrisense-old`), not in `urbora`.
- Keep the repo root lean: code goes in its folder, documents go in `docs/` (see `docs/MAP.md`). Superseded documents move to `docs/archive/`; they are not deleted.

## Frontend rules (anti-slop + farmer-first)

Design for the actual user: a farmer on a cheap Android phone, possibly outdoors in sunlight. Judges score function, not decoration.

Banned: purple/blue "AI startup" gradients, glassmorphism/blur panels, decorative shadows/glows, abstract blobs and wave backgrounds, hero landing layouts, placeholder or fake content of any kind, template-energy sections.

Do instead:
- Hierarchy over decoration: spacing, size, and type communicate structure. Every element earns its place or gets deleted.
- Farmer-first: large touch targets (≥44px), high contrast (sunlight-readable), big Bangla type (Noto Sans Bengali), one clear primary action per screen, minimal scrolling to key numbers (profit, next task).
- Domain identity: earthy/agricultural palette, not SaaS defaults. Icons that aid low-literacy comprehension (💧 water, 🌱 sowing), never ornamental.
- Motion only when it explains something (e.g., trace events arriving).

Before finalizing any screen: clear primary action? every element purposeful? readable at arm's length in daylight? If in doubt, remove one layer of styling and strengthen hierarchy.

## 4. When in doubt

- Uncertain cross-boundary interface → ask the human, don't guess.
- Uncertain scope → it's gated; log the proposal.
- Uncertain whether data is real → treat as mock and label, or remove.
- Stuck >25 min on one bug → log, tell the human, switch tasks. The timeline outranks any single bug.
